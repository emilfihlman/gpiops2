# Project review — 2026-09-08

Raspberry Pi GPIO/PS2 keyboard experiment. Reviewed source revision

below.

## Findings

The source uses Python 2 print syntax and Raspberry Pi GPIO/uinput APIs. In
pui.py the accumulation c=c<<1+dta() shifts an initial zero rather than
appending the sampled bit; c therefore remains zero and cannot decode the
intended scan codes. This is a concrete source defect, left documented because
the hardware path was not exercised.

## Next action

Before reviving the project, choose the target Pi/runtime, correct and
fixture-test bit assembly, and validate timing/parity/release/extended-key
handling. Keep actual GPIO and virtual-keyboard access explicitly local; a
shared development VM is not the target device.

setup, input injection or keyboard event occurred.
